## The problem

In mid-2026 every AI host had its own way to embed an app: MCP Apps in Claude and goose, a different bridge in ChatGPT. Merchants wanted one integration, and nobody had shown a checkout where the agent can fill a cart but the human still proves who is paying.

## What I built

A shopping app that runs on every surface from one TypeScript codebase.

- **MCP tools** for browsing, cart editing, reviews and checkout. The agent can edit the cart, but it cannot place orders or take payment; checkout is handed to a merchant page.
- **One React bundle, registered twice**: as an MCP App (`text/html;profile=mcp-app`) and as a ChatGPT skybridge resource. The UI detects its host at runtime.
- **Express `createApp()`** serves both the MCP endpoint and checkout, over stdio, HTTP, or Vercel serverless.
- **A payment gate** with two paths: a WebAuthn passkey that produces an AP2-shaped Payment Mandate checked by four validation gates, or a digital credential presented over OpenID4VP across devices, bound to the amount.
- **Age (21+) and loyalty credentials**, fail-closed and scoped to the order.
- **Optional x402 settlement** on Hedera testnet. If settlement is configured and fails, the order does not complete.

```text
Claude / ChatGPT / goose
        │ MCP
        ▼
server.ts (tools) ──► cart store (memory or Redis)
        │ checkout URL (order encoded, stateless)
        ▼
payment gate ──► passkey or wallet credential
        ▼
x402 settlement (Hedera testnet)
```

## Decisions worth talking about

- **Serverless-correct state.** Orders travel base64url-encoded in the checkout URL, and short-lived ceremony state is carried in tokens instead of memory.
- **Demo honesty.** The public connector has no auth and one shared cart; a wallet-free `DEMO_MODE` exists but is off by default; the merchant is a mock and nothing is charged.
- **One UI, two host contracts**, with the ChatGPT bridge marked "not exhaustively confirmed" in the README rather than over-claimed.
