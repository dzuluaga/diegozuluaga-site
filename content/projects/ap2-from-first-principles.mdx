## The problem

AP2, Google's Agent Payments Protocol, is how an agent carries proof of what a user approved: which cart, which payment, under which limits. The official SDK works, but it hides the cryptography. Developers who already know A2A, UCP or verifiable credentials couldn't see what a mandate actually is on the wire.

## What I built

A course where every lesson follows the same five beats: **Frame, Build, Map, Inspect, Check**.

- **Lesson 0:** why agent payments need their own protocol.
- **Lesson 1:** the six roles and the user journeys.
- **Lesson 2:** checkout and payment mandates. Build them, verify them, detect tampering, then map them to the SDK.
- **Lesson 3:** selective disclosure with SD-JWT and key-binding JWTs, and the open payment mandate.

The cryptography is written from scratch: ES256 JWTs on top of the `cryptography` package, including the DER-to-raw signature conversion that libraries usually hide.

## Decisions worth talking about

- **Build first, then map to the SDK**, so learners understand what the SDK is doing for them.
- **The code is the source of truth.** Snippets on the site are imported from the tested lesson code, so the docs can't drift from what runs.
- **Pinned upstream.** The official SDK isn't on PyPI, so it is pinned to a specific git revision for reproducible builds.
- **Tracking the spec.** The course teaches AP2's move from Intent/Cart/Payment mandates to Checkout/Payment mandates with open and closed states.
